# 自然公園 区域判定マップ

指定座標・地図上の地点・現在地が、読み込んだ公園区域のどの地種区分に入るかを判定します。国立公園35公園・15,293区域を同梱しています。国定公園の全国データと公式区域図の図名・図番号の対応表は未収録です。

## 起動・検証

```bash
npm install
npm run serve
```

`http://127.0.0.1:4173` を開きます。ファイルを直接開く `file://` では動きません。別端末に公開する場合はHTTPSが必要です。

```bash
npm test
# 上のサーバーを起動した状態で実行。標準ではインストール済みGoogle Chromeを使用。
npm run test:browser
# Chromiumを使う場合:
npx playwright install chromium
BROWSER_CHANNEL=chromium npm run test:browser
```

## iPhone向けのURL公開（GitHub Pages）

1. GitHubのリポジトリで Settings → Pages → Build and deployment → Source を「GitHub Actions」にします。
2. `.github/workflows/pages.yml` を含む変更をmainへコミット・プッシュします。
3. Actionsの「Publish park map」が成功すると、Settings → PagesにURLが表示されます。通常は `https://fukaimon.github.io/NationalParkMap/` です。

このワークフローはLFSの実データを取得し、アプリの配信に必要なファイルのみをPagesへ配置します。ブランチから直接公開する方式ではLFSの区域データを配信できません。GitHub FreeでPagesを使う場合は公開リポジトリが必要です。非公開リポジトリからの公開は対応する有料プランが必要で、通常のPagesサイト自体は公開されます。

iPhoneのSafariで公開URLを開き、共有メニューからホーム画面に追加します。追加したアイコンからWi-Fi接続中に起動し、「オフライン判定の準備完了」を確認してください。その後、機内モードかつWi-Fiオフで再起動し、判定できるか確認します。背景地図のオフライン保存は未対応です。

## 使い方

1. 初回は通信可能な状態で開き、区域データの読込と「オフライン判定の準備完了」を待ちます。判定データは約150 MiBあり、初回読込・保存に時間がかかります。
2. 地図にはクリック前から区域を地種区分別に色分け表示します。右上の「区域図」のチェックで表示・非表示を切り替えられます。追加した区域も表示対象です。縮小時の境界線は表示用に簡略化し、地点の判定には元の座標を使います。
3. 緯度・経度を入力、現在地ボタン、または地図クリックで判定します。地名検索は候補を選んで判定します。地名の座標は代表点です。
4. 公園名・地種区分・境界からの概算距離・出典・基準日を表示します。境界上と近傍候補は区別し、重なった区域は全て表示します。
5. 「区域を追加」でGeoJSON/KMLを併用できます。同名ファイルは置換し、別名ファイルは追加します。追加データは収録範囲の詳細を開いて削除できます。

## オフラインでできること

- 画面とローカルのLeafletをService Workerで保存し、区域データをIndexedDBに保存します。
- 保存後は、通信遮断・ページ再読込後も座標と現在地による判定ができます。現在地取得そのものは端末・測位環境・位置情報権限に依存します。
- 地図ライブラリの欠損や背景タイルの取得失敗でも、Worker内の判定は実行します。
- 背景地図・航空写真のオフライン保存は行いません。地名検索にも通信が必要です。
- 初回未読込、端末保存容量の不足、ブラウザによる保存領域の削除は画面上で区別します。未読込を「区域外」と判定しません。ブラウザがデータを削除した場合は再準備が必要です。
- 「同梱データを再読込」は、このサーバーに置かれたGeoJSONを再取得します。環境省サイトから最新版を自動取得する機能ではありません。

## 精度と判定の扱い

概略サンプルへの自動フォールバックを廃止しました。同梱のShapeデータから座標を丸めず変換し、Polygon・MultiPolygon・穴・境界・重複を扱います。bboxは再計算し、不正な区域は黙って除外せずファイル全体を拒否します。元データの自己交差や穴の包含関係など、GISトポロジーの全面検証は未実装です。

境界の数値判定に用いる許容差は `1e-10` 度です。GPSの精度半径と20 mの近傍目安は注意表示のためだけに使い、公園の区域を拡大しません。距離は日本付近での局所平面近似で、元図の位置誤差を保証する値ではありません。

元Shapeの `.prj` はJGD2000です。元座標を保持して緯度・経度として照合していますが、WGS84との厳密な測地系・元期変換は未実施です。高精度な境界判定にはこの補正と原図照合が必要です。

同梱Shapeの取得日・各区域の告示基準日は確認できないため「未確認」と表示します。ファイル生成日時を区域の更新日には使いません。公式データ自体も概要を示すもので誤差を含むと説明されています。[環境省・生物多様性センター](https://www.biodic.go.jp/nps_nwp_nca_cz.html)

## データ変換

```bash
# 公式ZIPを展開してvendor/npsに nps.shp / nps.dbf / nps.prj を配置
npm run convert:nps
npm test
```

変換は既知のJGD2000経緯度データのみ受け付けます。未知の投影座標系をそのまま経緯度として書き出しません。元属性と座標精度を保持し、全件検証を通った後にGeoJSONを更新します。

## 追加ファイルの仕様

GeoJSONは `FeatureCollection`、各地物は `Polygon` / `MultiPolygon`。WGS84の `[経度, 緯度]` を使い、リングを閉じてください。KMLは標準の `経度,緯度[,高度]` の順で、Polygonの外周と内周を扱います。座標の自動入替はしません。線・点・NetworkLink・KMZ・PDFは判定区域として取り込みません。KMLの未閉鎖リングは最後を最初の頂点で閉じます。

推奨する地物のproperties:

| 属性 | 内容 |
| --- | --- |
| `parkName` | 公園名 |
| `parkType` | `国立公園` / `国定公園`（省略時は種別未確認） |
| `zoneName` | 特別保護地区、第1〜3種特別地域、普通地域、海域公園地区など |
| `source` | 出典 |
| `sourceDate` | 区域の基準日・改訂日（未確認なら省略） |
| `mapSheet` | 対応する公式区域図の図名・図番号 |
| `mapUrl` | 対応する区域図のHTTP(S) URL |

`NAME` / `ZONE`、`park_name` / `zone_name`、`公園名` / `地種区分` なども認識します。国土数値情報の属性コードは年度で意味が違うため、自動推測しません。取り込み前に仕様に対応した属性変換が必要です。データセット全体の基準日表示にはFeatureCollection直下の `sourceDate` を指定してください。

## 構成

- `src/geometry.js`: 地図・通信・DOMに依存しない区域判定
- `src/area-worker.js`: 読込、検証、データセット管理、判定を別スレッドで実行
- `src/storage.js`: IndexedDBへの保存・復元・削除
- `src/kml.js`: KMLのポリゴン・属性変換
- `src/app.js`: 検索・位置情報・判定表示、任意の地図表示
- `sw.js`: 画面とローカル資産を保存（配信更新時はCACHEの版を変更）

全国対応に不足するデータ・精度・運用の詳細は [全国対応に向けた課題](docs/nationwide-readiness.md) にまとめています。
