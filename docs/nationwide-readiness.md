# 全国の国立公園・国定公園への対応状況

調査・実装日: 2026-09-06

## 現時点でできること

同梱Shapeから35の国立公園、15,293の地種区分ポリゴンを確認しました。手元の全件を再変換・検証し、指定点の公園名と地種区分を照合できます。国定公園は追加GeoJSON/KMLの範囲を判定できますが、全国分は同梱していません。

「地種区分に入ること」と「どの公式区域図の図面に該当するか」は別です。元データの属性はNAMEとZONEのみで、区域図の図名・図番号・URLを特定する情報がありません。今回、`mapSheet` / `mapUrl` を持つ追加データの表示には対応しましたが、公式図面との対応表は作成できていません。現在のデータだけで図番号を推定することはしていません。

## 全国対応に不足するもの

| 優先度 | 不足 | 必要な対応 |
| --- | --- | --- |
| 最優先 | 国定公園の全国区域・地種区分 | 公園ごとに公式GISまたは区域図を収集。都道府県をまたぐ区域を統合し、普通地域・海域を含めて収録範囲を照合する。 |
| 最優先 | 公式区域図との対応表 | 公園ID、図面ID、図名、図郭ポリゴン、版、URLを整備。図郭が重なる場合は該当する全図面を返す。区域ポリゴンとは別データとして管理する。 |
| 最優先 | 基準日・改訂履歴 | データ提供日、取得日、告示日、図面改訂日を分離し、公園ごとに更新台帳を作る。生成日時だけで最新版と判断しない。 |
| 高 | 座標系と幾何品質 | JGD2000/JGD2011/WGS84、投影法、元期を確認して統一。自己交差、外周外の穴、スリバー、海域の欠損、異なる地種区分の重複をGISで検査する。 |
| 高 | 精度の実測 | 原図または管理者確認済み地点を公園・地種別に用意し、境界の両側、穴、飛び地、共有境界を比較検証する。現在のテストは判定アルゴリズムと代表地点の確認であり、全国の法定境界の正確性を証明しない。 |
| 高 | モバイル容量・速度 | 現在約150 MiBの全データを読み込む。公園別パッケージ、空間索引、選択ダウンロード、保存容量表示、版ごとの原子的更新を導入する。低メモリ端末の測定が必要。 |
| 中 | 検索と測位の現地品質 | 地名代表点と目的地点の差を確認できるUI、必要ならオフライン地名辞書。GPSの測位精度だけでなく測位環境の実機検証を行う。 |

## 調査した公式情報

### 国立公園GIS

[環境省・生物多様性センター「国立公園区域等」](https://www.biodic.go.jp/nps_nwp_nca_cz.html) は、全国のShape、公園名・地種区分を提供しています。掲載上のダウンロード更新日は2025年4月28日で、原図縮尺は公園ごとに異なり、概要を示すデータで誤差を含む旨が説明されています。手元のZIPとの版の一致は検証できていないため、この更新日を同梱データの基準日として付与していません。

### 国定公園の収集元

[環境省の国定公園一覧](https://www.env.go.jp/nature/nationalparks/about/quasi-national-park/) を収集台帳の出発点にし、各公園の管轄自治体の公式区域図・公園計画と照合する必要があります。[公園計画の見直しの説明](https://www.env.go.jp/nature/exp_parkplan/index.html) もあるため、名称一覧を集めるだけでなく区域変更の追跡が必要です。

[EADASのGIS情報説明](https://eadas.env.go.jp/eiadb/ebidbs/Service/About?title=Gis) も出典・収録時点の調査先です。画面上で表示できることと、アプリ用に再配布できるデータが得られることは別なので、形式・提供条件・更新時点を確認してから取り込みます。

### 国土数値情報A10をそのまま採用できない理由

[国土数値情報「自然公園地域データ」](https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-A10-v4_1.html) は候補ですが、年度で法的な基礎や分類体系が異なります。掲載では2010年度版が自然公園法、2015年度版などは国土利用計画法に基づくと区別されています。後者は土地利用基本計画の自然公園地域で、細区分は参考表示とされています。古い全国データを追加しただけでは、現在の国立・国定公園の全ての地種区分を正確に判定できるとはいえません。掲載される利用条件も取り込み対象ごとに確認が必要です。

## 推奨する次の実装順

1. 対象公園ごとに、公園ID・種別・出典・版・収録地種・欠損・座標系の台帳を整える。
2. 国定公園1件で取得から変換、区域図対応、基準地点照合までの流れを確立して、全国に展開する。
3. 公園別のオフラインパッケージと空間索引を導入し、スマートフォンで容量・起動時間を測定する。
4. 公式図面の図郭索引を追加して、「この地点を載せた区域図」を直接選べるようにする。
5. 更新検知、差分検証、旧版への復帰、全国網羅チェックを自動化する。
